RETURN CONTRACT CHECKLIST
Sources: WORK/RETURN-GUIDE.md; WORK/package_return.py; repo/src/arcpuzzles/review_full_return.py; review_full_draw.py (public duties template); review_return.py and review_evidence_bundle.py (public packaging helpers).
No packaging, start, audit, source mutation, or solve-private inspection was performed for this checklist.

1. RESULTS.json (editable input at WORK/RESULTS.json)
Supply exact keys: completion_state (complete|blocked|in_progress), stopping_reason, modified_components (list), remaining_failures (list), verification_commands (list). Optional curriculum is specially bound and validated; omit unless used deliberately.
Each verification_commands entry uses cwd (nonempty relative directory, no absolute path or '..'), argv (nonempty list of nonempty strings without NUL), exit_code (actual integer or null for unknown), evidence_paths (list of retained workspace-relative paths). Include source SHA-256 in retained command evidence and opening REVIEW.md brief. Additional per-command fields can preserve a source hash because entries are retained as given.
The guide uses 'packet_root' as a WORK-root sentinel; direct repository commands normally use 'repo'. For unambiguous concrete WORK-root commands use cwd='.'; wrapper payload cwd is repo. A fresh-copy command must identify its actual runtime working directory in evidence rather than guessing source depth.
The builder generates/overwrites final keys: schema='arcpuzzles-full-results-v2', assignment_id, generator_id, completion_state, stopping_reason, modified_components, remaining_failures, verification_commands, artifacts. artifacts entries are {path,kind,sha256}; INTAKE.json is automatically derived. Do not hand-write INTAKE.json or artifact hashes.
Caution: arbitrary top-level RESULTS fields are dropped by the builder; only optional curriculum is additionally carried through.

2. Required documents and assignment
Unchanged ASSIGNMENT.json; REVIEW.md; DECISIONS.md; QUESTION_ANSWER.md; FEEDBACK_TO_CODEX.md. Drawn AUDIT_ASSIGNMENT.json requires AUDIT.md with exactly one nonempty '## TASK_ID' section per each of its two targets. BLIND_ASSIGNMENT.json and public blind-solve records are preserved when required.
First 8–12 REVIEW.md lines: task/version; defect and repair; final source hash; checks actually run and final counts; blockers or none; any Racket authority change; 'Acceptance: routine' or precise 'Acceptance: needs attention'. For lesson claims include demonstration count, ordering/query policy, production and rotation verdicts/counts; untested means unknown.
Complete status requires valid required fresh repaired-source solve and blind solve. Preserve genuine failed iterations and honest exposure declarations.

3. Required check commands (all issued from WORK/, replace TASK_ID and use fresh output paths)
python3 run_with_racket.py python3 -m arcpuzzles check TASK_ID --battery --timeout 4000 --phase before --out ../checks/before
python3 run_with_racket.py python3 -m arcpuzzles check TASK_ID --battery --timeout 4000 --phase after --out ../checks/after
python3 run_with_racket.py python3 -m arcpuzzles check TASK_ID --stage task_tests --timeout 600 --phase after --out ../checks/task-tests
Task tests are not discovered by the general battery/root pytest; run explicitly. Frozen inherited test preflight failure must remain blocked. Missing/all-skipped tests are not passes. After gates: lint/defect lint (no blockers/warnings), rule authority/smoke, lawful self-check/strict profile, at least one canonical-size/palette profile hit in each band’s 20 draws, advertised exact overrides honored or incompatible, executable semantic witnesses/rivals and teaching support.
Conditional lesson census for plausible canonical-fitting rivals:
python3 run_with_racket.py python3 -m arcpuzzles lesson-census TASK_ID --per-band 100 --rotate-query --timeout 1800 --out ../checks/lesson-census.json
If arbitrary rotations claimed, require --require-rotations-identifiable on semantic_gate/battery; intentionally ordered curriculum census uses --rotation-policy diagnostic. Declared LESSON_SCHEDULE_PERIOD additionally calls for --enumerate-schedule-period --schedule-seed 0 with explicit rotation policy and a fresh output.
Optional audit checks are separate --phase audit, not substitutes for selected-task after verification.

4. Fresh original-packet replay (reviewer-owned handoff)
Extract the ORIGINAL input ZIP into a distinct fresh directory; enter its WORK/.
git init -q
git rev-parse --show-toplevel
Confirm this is exactly fresh WORK/ (not a parent repository).
git apply --check /absolute/path/to/patches/source.patch
git apply /absolute/path/to/patches/source.patch
If Git root is the outer extraction instead, execute both git apply commands there with --directory=WORK.
Check EVERY changed path including new files; compute repaired generator SHA-256 and compare to final measured source hash. Exit 0 alone does not prove application. Replay focused regression tests and preferably required after checks above in the fresh copy, retain exact command/cwd/exit/source hash and logs under the returned checks/. Apply patch-created task tests/workspace files as well as generator.
Portable task tests must use reviewer_support.find_root(__file__), canonical_path and canonical_pairs. Generator authoring probes use load_selected_generator(ID, root=find_root(__file__)) and the public review.py run wrapper; avoid private generator aliases.
Verify final solve summary binds those same generator bytes. If generator changes after solve, retain prior solve under checks/prior-solve and prepare new final episode.
Self-review for new shortcuts/distribution restrictions and state witness/limitations.

5. Packaging scope and evidence selection
Builder automatically computes patches/source.patch against .review/baseline. Allowed edits: selected task generator.py, notes.md, SUMMARY.md, workspace/, tests/, counterexamples/; selected canonical row; declared baseline shared/data/base files. No unrelated repo changes/new files, deletes, binary/rename/mode patches, executable files or symlinks. Do not copy the entire repository/library into checks/.
Every file recursively under WORK/checks/ is automatically included, with no exclusion patterns; symlinks reject. Select decisive new reports, failures and reproducible witnesses BEFORE package. Do not remove the only retained failure copy just to fit budget. Reference earlier retained ZIP and its SHA explicitly if relying on it.
All ordinary public solve/ and solve-blind/ files are included except hidden paths and __pycache__; packaging also inserts frozen generator snapshots without requiring reviewer inspection of private sources.
Outer limits are <=256 ZIP members and <=25*1024*1024=26,214,400 expanded bytes (inclusive validator limits). To satisfy a strict requested '<256'/'<25MiB', aim below those boundaries.
When projected members exceed 256, builder automatically bundles ALL checks/ files into EVIDENCE-BUNDLE.tar.gz + EVIDENCE-BUNDLE.json; --bundle-evidence forces this. Bundle supports <=4096 check files. Bundling does NOT relax expanded-byte budget: original check-file bytes replace compressed bundle length in size accounting. It only solves the outer member count. Evidence references keep original checks/... paths and are validated against the manifest.
Do not put a fresh full extraction/runtime copy under checks/: it will be included, may exceed bytes, and is unnecessary for replay evidence.

6. Build commands (checklist only; not executed by this helper)
From WORK/:
python3 package_return.py --out review_response_ASSIGNMENT_ID.zip
or python3 package_return.py --bundle-evidence --out review_response_ASSIGNMENT_ID.zip
Output must not already exist. Builder checks source scope/baseline, emits canonical RESULTS/INTAKE and hashes, checks budgets before writing, statically validates completed ZIP including CRC and solve payload, and deletes the ZIP if post-write validation fails. Record exact final ZIP SHA-256 and size/count separately after success.
