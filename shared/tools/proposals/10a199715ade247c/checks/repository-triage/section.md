**Managed-job diagnostic scope:** `check_jobs._birth(pid)` reads `/proc/<pid>/stat`; `status()` declares a running supervisor disappeared if this returns `None`. In one actual wrapper-process probe, `os.getpid()` was 2 but `/proc/2/stat` was absent and `_birth(2)` returned `None`, while `/proc/self/stat` existed. In an extended probe, `os.getpid()` was 5, `/proc/5/stat` described `sync_share.sh`, and `/proc/self/stat` reported PID 15487. Thus the numeric process IDs exposed to these Python processes do not reliably identify their corresponding `/proc` entries in this environment. Retained supervisor evidence eventually reports `stage_failed`, exit 1, resumable true, with `pid_birth: null` and the expected `checkpoint` output. This explains the observed premature disappearance classification; it does not certify detached-job behavior on a normal host or exclude every possible race.
