# Decisions for ba1bd4c08c37

## D1 / R1 — reject scalar aliases at the public boundary

**Input choice.** `seed` and `sample_index` must be exact Python integers
(`type(value) is int`) and nonnegative in both `generate` and
`schedule_profile`.

**Rationale.** The baseline accepted values such as `True`, `1.75`, `'1'`, and
`-1`. Some aliases select the same random stream or schedule slot as a different
nominal input; negative indices also wrap the six-profile schedule. That makes
episode identity and split accounting depend on implicit Python coercion rather
than the declared API.

**Alternatives rejected.** `isinstance(value, int)` was rejected because it
accepts `bool`. Calling `int(value)` was rejected because it silently aliases
floats and strings. Validating only inside `gen_ctx` was rejected because
`schedule_profile` indexes before that boundary and needs the same contract.

**Probe and failure mode.** The baseline battery's defect lint emitted 33 strict
scalar warnings. The focused tests first failed against the old source, then
covered Boolean, float, string, `None`, and negative values for both public
functions. The minimal record is
`generators/ba1bd4c08c37/counterexamples/strict-public-scalars-v1.json`.

## D2 / R1 — keep lawful generation and Racket authority unchanged

**Decision.** The repair changes only argument validation and bumps the generator
version from `2.0.0` to `2.0.1`. The six-profile curriculum, axes, distribution,
validators, rivals, rule hash, and selected Racket source remain unchanged.

**Rationale.** Baseline evidence already showed the canonical generator's grid
semantics, profile support, overrides, labels, and lessons were healthy. Bundling
a distribution or authority edit with the scalar fix would make causality harder
to verify and could introduce a new shortcut.

**Alternative rejected.** Refactoring `generate` around a new context object or
rewriting the schedule was unnecessary. The smallest root-cause repair is one
shared validator called before the existing flow.

**Verification.** Final rule smoke has 120/120 valid executions and 120 distinct
outputs. The final override matrix has 45,000 accepted exact draws and zero
findings. The canonical authority remains `RULE_HASH=5394b465fb89`.

## D4 / R2 — prototype `output_corner` as an isolated episode-level rule parameter

**Parameter.** `output_corner ∈ {top_left, top_right, bottom_left,
bottom_right}`. It is chosen once per episode from the deterministic episode
seed; `top_left` remains the canonical default.

**Why this parameter.** It changes the transformation while preserving the
existing input family, output dimensions, palette, and bbox semantics. The four
settings have a natural common interface and are easy to express as small Racket
source variants. This makes the parameter useful for studying whether examples
teach a rule choice rather than merely a surface distribution.

**Input constraint.** Retain only production-valid inputs whose four raw corner
crops are pairwise distinct. Without this filter, a seed quadrant symmetric about
an axis could make two corner settings extensionally identical and create a
lesson that cannot reveal the selected rule.

**Alternatives rejected.** Parameterizing output color would confound a fixed
symbol role rather than a structural rule. Parameterizing crop size would overlap
the canonical fixed-size shortcut problem and require a larger validity contract.
Integrating the corner enum directly into production was rejected because the
assignment asks for a nearby prototype and canonical acceptance must remain
separate.

**Evidence.** Four Racket programs were materialized. Each setting has five
demonstrations and one query; labels come from Racket execution, all pairs
separate all settings, and all six query rotations are identifiable. Evidence is
under `checks/parametric/output-corner-v1/`.
