# Parametric quadrant-priority direction — proposed prototype

This task-local prototype varies one episode-level rule parameter while preserving
all four original object roles, coordinate alignment, transparency, and quadrant
overlay reasoning:

| Parameter | Allowed values | High-to-low priority | Original/default |
| --- | --- | --- | --- |
| `priority_mode` | `canonical` | `TR > BL > BR > TL` | yes |
| `priority_mode` | `reversed` | `TL > BR > BL > TR` | no |

`canonical` returns the selected canonical Racket program byte-for-byte. The
`reversed` setting changes only the four precedence steps. One setting is chosen
once per episode and remains fixed for all three demonstrations and the query.

Each controlled input is an even rectangular four-quadrant grid with background
0, one distinct nonzero color per quadrant, and shuffled conflict coordinates.
Every demonstration contains conflicts that make the two priority modes produce
different outputs. Labels and rival outputs are generated by executing the exact
materialized Racket text with the included bridge; no Python label mirror is used.

Run from the outer extracted packet directory:

```sh
python3 review.py run python3 \
  generators/18a3c532c9dc/workspace/parametric/prototype.py \
  --seed 75 --out ../checks/parametric/priority-gallery

python3 review.py run python3 -m pytest -q \
  generators/18a3c532c9dc/tests/test_parametric_priority.py
```

The gallery writes two complete private episodes, masked public challenges,
exact `.rkt` programs and hashes, a shared-input setting-difference witness,
a canonical-default replay check, runtime identity, source hashes, and a report.
This is a **proposed prototype**, separate from the fixed-rule production generator.

Limits: two priority settings, two retained seeds, controlled fixtures, one query
per episode, and only the declared opposite setting as a rival. The evidence is
finite and does not grant production approval or establish identifiability against
all possible overlay orders or shortcuts.
