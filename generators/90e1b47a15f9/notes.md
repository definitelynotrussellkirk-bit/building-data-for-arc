## Reversed decision: random scatter → constructive semantic maze

The prior generator scattered markers in a mostly open bordered room. Retained audit `review-cd76f14ab38151f7:v0001` found that deleting all keys and doors changed 0/36 sampled outputs; medium/hard solutions crossed a door in 0/24 samples. The prior design was therefore retired.

The current generator builds a randomized DFS perfect-maze graph, chooses a semantic placement, and renders only the connected corridor subtree used by that placement. Unused cells remain color 8, preserving the wall-dominant, one-cell-corridor character of the canonical inputs while still varying topology and reflection by seed.

## Lesson schedule

A generated lesson has five demonstrations and one query. The period-three profile schedule is:

- `two_stage_detour`: both key/door pairs are causally required; each key is on a side branch before its matching route door.
- `unreachable`: key 4 is behind door 6; the intended output is all zero, while erasing locks or letting either key open both doors creates a route.
- `bypass`: both key/door pairs are dead-end branches; the true shortest route ignores them.

Every six consecutive generated pairs contain each profile twice. Holding out any one query therefore leaves all three profiles among the five demonstrations. Task-local tests exhaust cyclic starts and held-out positions. The source-bound census materialized 100 lessons per difficulty band: 300/300 lessons, 1,800 pairs, 1,798 unique inputs, and 1,800 rotations, with zero ambiguity, hook warnings, or scoring errors against the declared rivals.

# Decisions for 90e1b47a15f9

## D1 — Preserve the pinned Racket authority

**Original choice:** stateful BFS over `(row, column, has-key-4, has-key-5)`, with key 4 opening door 6 and key 5 opening door 7.

**Decision:** keep the Racket rule and canonical row unchanged. Pin `RULE_HASH`; add a Python mirror only for local tests and rival probes.

**Evidence:** all four canonical labeled pairs replay through both the independent Python oracle and production mirror; rule smoke and authority synchronization pass. Changing the authority would have hidden a sampler defect rather than fixing it.

**Limit:** the Python mirror is not label authority; Racket labels the retained witness, battery, census, and solve instance.

## D2 — Replace open-room scattering with constructive sparse corridor trees

**Prior choice:** independently scatter start, goal, keys, doors, and a few walls in an otherwise open rectangle.

**Failure:** retained audit `review-cd76f14ab38151f7:v0001` measured no output change after deleting colors 4–7 in 36/36 samples and no door traversal in 0/24 medium/hard solutions. Baseline lint, defect lint, and distribution gates also failed.

**Decision:** generate a randomized DFS perfect-maze graph, select a semantic placement, and render only its connected subtree. Unused cells remain walls.

**Rejected alternatives:**

- Increasing random wall density: frequency does not guarantee key-before-door causality.
- Keeping straight-line templates: an early TDD prototype established semantics but failed the desired topology/morphology diversity.
- Modifying the Racket rule: canonical replay showed no rule defect.

## D3 — Schedule three explicit semantic profiles

1. `two_stage_detour`: both matching key/door transitions are required.
2. `unreachable`: key 4 is behind door 6, producing a lawful all-zero output.
3. `bypass`: the shortest path ignores both dead-end key/door branches.

**Rationale:** the canonical pairs all fit three plausible shortcuts—erase keys/doors, one key opens both, and always collect both keys. Required, impossible, and irrelevant cases together distinguish roles rather than merely displaying symbols.

**Failure modes addressed:** a required-only curriculum could teach “always collect both”; a bypass-only curriculum could teach “ignore locks”; a reachable-only curriculum could omit the all-zero endpoint.

## D4 — Guarantee five-demo query rotations

`EXAMPLES_NEEDED = 5`; the materializer forms six labeled pairs and holds out one query. A period-three schedule puts each profile twice in every six consecutive pairs, so any held-out pair leaves all three profiles among five demonstrations.

**Verification:** focused tests exhaust starts `0..17` and all six held-out positions; the semantic gate requires rotations; the census checks 1,800 rotations. Production and rotation verdicts are both `no_ambiguity_found` against the declared rivals.

**Limit:** this is finite-rival evidence, not a proof that every possible rule is excluded.

## D5 — Advertise only exact, observable axes

**Prior choice:** palette, density, position, and texture controls were dead or overlapping.

**Decision:** expose only `grid_h` (7–13), `grid_w` (12–18), and `route_profile`. No incompatible combinations are declared because every legal height × width × profile × difficulty tuple is constructive and observed.

**Evidence:** the final override stage passes its complete matrix; focused tests separately exercise 36 representative exact combinations and malformed overrides.

## D6 — Balance canonical support and controlled size extensions

Four of every five default samples use exact canonical dimensions: 7×12, 8×13, 9×14, or 8×14. Every fifth uses a difficulty-banded extension through 13×18.

**Rationale:** preserve canonical morphology/profile-floor support while allowing complexity variation. Palette and marker multiplicities remain exact.

**Limit:** generated inputs are sparse orthogonal corridor trees; cyclic/open lawful grids remain outside the production sampler.

## D7 — Declare and constrain the all-zero endpoint

The rule's all-zero output is lawful when no key-state path reaches the goal. `unreachable` intentionally exercises it, but `self_check` and generation require that erasing locks restores a route.

The first repaired defect-lint run flagged the endpoint because it lacked a declaration. `SOLID_OUTPUT_JUSTIFICATION` was then added under a failing-first regression test; the clean rerun passes.

## D8 — Make rivals and witnesses executable

Declared rivals are `erase_keys_and_doors`, `doors_are_walls`, `one_key_opens_both`, and `always_collect_both`. Matching witnesses and `lesson_identifiable` are executable. `workspace/two_key_probe.py` independently implements the state machine and proves the three canonical shortcuts fit 4/4 canonical pairs.

The minimal exact disagreement is retained in `counterexamples/erase_keys_and_doors.json` and replayed by a focused test. Racket authority and both Python implementations agree on the intended output.
