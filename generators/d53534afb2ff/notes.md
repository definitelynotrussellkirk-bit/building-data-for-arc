# Decisions

## D1 — Treat the defect as a curriculum failure, not only missing hooks

**Measured baseline.** The selected v1.3.0 source had SHA-256
`104bb9d1fbce372c9e7985ad8f84a8da99b12057997ff81833a3ace21175280f`.
It omitted `RULE_HASH` and `self_check`, and declared several inert axes. More
importantly, a 600-draw baseline probe (200 per band) produced zero connected
multi-cell targets and zero outside objects; every enclosed target was a single
cell. That left whole-object recoloring and unchanged outside controls
unexercised. Evidence: `checks/baseline-manifold.json` and `checks/before/`.

**Decision.** Replace the sampling curriculum rather than merely adding metadata
and a validator. A hook-only patch would satisfy lint while preserving the
shortcut manifold.

## D2 — Keep the Racket authority unchanged

The canonical program already implements the intended containment transform and
passes all canonical pairs. The problem was generated support, not authority
semantics. The selected generator now pins `RULE_HASH = "372b08419c67"`; no
Racket source or canonical data was edited. Authority sync and rule smoke pass.

Rejected alternative: broaden or rewrite the Racket rule. There was no failing
canonical or generated lawful input requiring such a change, so that would add
unnecessary review risk.

## D3 — Advertise one exact semantic axis

The old eight-axis surface mixed geometry, palette aliases, constants, and
negative textures that were either inert or outside the ordinary rule domain.
The repair exposes only `scene_profile`, whose value can be recovered exactly
from pixels by `observe_overrides`.

The four values are:

1. `two_singletons` — canonical-shaped baseline with two frames;
2. `outside_same_color` — a same-color object outside all frames remains fixed;
3. `multi_cell` — one enclosed connected object has at least three cells;
4. `multiple_inside` — one frame contains multiple non-color-3 objects.

A deterministic four-example cycle guarantees every consecutive four samples
cover all values. Exact override tests cover every value in every difficulty
band. Rejected alternative: retain cosmetic axes for apparent diversity. An
unobservable control is worse than no control because checkers and lesson
builders cannot verify it.

## D4 — Use constructive layouts, not rejection with a graceful invalid fallback

The old source attempted random placements and returned the last partial grid
after exhaustion. The repair enumerates legal frame layouts and object
placements, then chooses deterministically through `GenCtx`. Generation either
constructs the requested profile or raises a precise internal error; it never
silently returns a partial lesson.

This also keeps global `random` state untouched and makes seed/sample replay
stable. The retained tests check deterministic fresh generation and global-RNG
purity.

## D5 — Make the executable contract independent of generation metadata

`analyze_scene` derives exact frames, connected components, containment, and the
observable profile from pixels. `self_check`, `strict_canonical_like`, and
`rule_mirror` use this pixel-derived analysis. Canonical inputs are accepted even
though they were not generated by the new builders.

Rejected alternative: validate from hidden generation metadata. That would not
protect hand-authored counterexamples, canonical examples, or copied portable
runtimes.

## D6 — Encode the actual rival rules and their witnesses

Three rivals fit all 3 canonical pairs:

- recolor only enclosed objects originally colored 3;
- recolor only enclosed objects of at most two cells;
- recolor only the first object in each frame.

A fourth lesson competitor recolors matching colors globally, including outside
objects. Each rival is executable, paired with a semantic witness, and checked
against generated lessons. The final reusable probe sampled 2,400 inputs and
1,200 cyclic lessons: all four profiles appeared 600 times, every rival received
an exact disagreement witness, and zero complete lessons left a declared rival
unresolved. Evidence: `checks/review-probe-final.json`.

Rejected alternative: prose-only claims about diversity. Counts of shapes or
colors do not establish that a concrete rival is excluded.

## D7 — Preserve canonical-scale support while adding discriminating cases

All generated canvases stay near canonical dimensions and palettes. The profile
floor accepted all three canonical inputs and found canonical-envelope support
in every band (easy 14/20, medium 18/20, hard 15/20). The curriculum adds only
semantically relevant variation; it does not introduce nested/overlapping frames
or ambiguous multi-frame containment.

Remaining limit: the finite rival set is not a proof of universal induction.
Generated scenes intentionally use one or two disjoint exact rectangular frames,
background 0, and connected monochrome objects. Those boundaries are explicit
rather than accidental.

## D8 — Add a reusable source-bound probe

`workspace/review_probe.py` reads the generator's live
`CANONICAL_SHORTCUTS`/`LESSON_COMPETITORS` declarations, verifies every
canonical-fit claim, materializes the first generated disagreement for each
rival, and checks all four cyclic lesson starts. A portable smoke test prevents
the tool from silently drifting from the selected generator.

## D9 — Keep `EXAMPLES_NEEDED` as a literal source constant

The first exposed-solve preparation failed even after the twelve-stage battery
was green because `review_solve._demonstration_count` statically reads the
assignment and accepts only a literal integer. `EXAMPLES_NEEDED =
len(SCENE_PROFILES)` evaluates correctly at import time but is not accepted by
that source parser. The blocked episode is retained under
`checks/prior-solve/nonliteral-examples-needed/`.

The final source uses literal `EXAMPLES_NEEDED = 4`, and a source-AST regression
test now enforces this integration contract. This is intentionally redundant
with `len(SCENE_PROFILES)`; the same test also verifies the value and profile
set, so drift fails loudly.

## D10 — Randomize role colors after the final shortcut self-review

The first structurally repaired draft used a fixed palette for each profile,
which closely mirrored the canonical examples. That was not a rule-execution
bug, but it created an avoidable distribution restriction: canvas/profile shape
could reveal a memorized frame/target color map.

A failing regression test first demonstrated one palette signature per profile
across 32 seeds. The selected source now samples distinct frame and target role
colors through `GenCtx` for every example; the `multiple_inside` targets exclude
color 3 so that profile remains a guaranteed witness against the color-3-only
rival. The final reusable probe reports and enforces multiple role-palette
signatures per profile. Rejected alternative: document the fixed palette as a
limitation, because removing it was cheap and made the lesson materially less
shortcut-prone without changing the Racket authority.
