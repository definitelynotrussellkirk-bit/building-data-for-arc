## G1: all seeded frames and marker multiplicity

The canonical written and executable rule fills every blue frame containing at least one red interior cell. The old one-frame restriction and `multi_seeds` negative fixture contradicted the canonical test. The original author's deeper rationale is unknown; the module summary simply repeated that restriction. The repair samples one through four active frames subject to `n_seeded <= n_frames`, and one through four markers in each active frame. The validator accepts heterogeneous counts and all three canonical inputs.

An initial proposal used uniform markers per active frame. Independent review identified a rival that fills only frames tied for the greatest positive marker count. It fits all canonical pairs and would fit that uniform sampler forever. The chosen exact axis is therefore **max_seeds_per_frame**, observed as the realized maximum. When there are multiple active frames and the maximum exceeds one, the constructor guarantees both a one-marker frame and a maximum-marker frame, with remaining counts randomized. This makes selection by greatest count observably wrong. No output labels are generated by these Python rivals.

## G2: exact controls and color roles

| Control | Domain | Realized meaning / choice |
|---|---|---|
| grid_h, grid_w | 9..20 | Exact returned dimensions, available in every difficulty band |
| n_frames | 2..4 | Number of complete disjoint blue perimeter components |
| n_seeded | 1..4 | Number of frames with positive interior marker count; cannot exceed n_frames |
| max_seeds_per_frame | 1..4 | Exact maximum positive interior marker count |
| n_outside_seeds | 0..3 | Exact red cells outside every frame bounding box |

All six are recovered from pixels. Unknown names, bool/float/string/None values, and out-of-range values raise ValueError. Impossible `n_seeded > n_frames` has a structured `incompatible_axes` declaration. If only n_seeded is pinned, the free frame count is drawn from feasible values rather than failing due to an unrelated default. Difficulty reweights free draws but never narrows the explicit domain.

The palette remains fixed: black 0 background, blue 1 frames, red 2 markers; yellow 4 is output-only. Recoloring these semantic roles would change the task. Old palette/texture/density/position pseudo-controls were ignored or unobservable and have been removed instead of relabeled as working controls. Callers using them now receive a useful error. The old 7..16 metadata already contradicted the actual draw ranges. The new minimum 9 permits a constructive four-frame, capacity-four boundary; maximum 20 broadens scale while keeping checks inexpensive.

## G3/G4b: constructive placement and bounded domain

Repeated random packing with a fixed attempt cap could fail despite feasible requests, and the old double-padded overlap test excluded one-cell gaps. The new constructor partitions the canvas into row bands with one-cell gaps, then independently partitions each row into its required frame slots. Every slot is at least 4x4. A 4x4 frame holds four interior markers, and four such frames with one-cell gaps fit 9x9; this proves the advertised maximum count combination is feasible at the minimum canvas size. Spare cells are distributed randomly and each frame's dimensions/position are independently drawn within its slot.

The intermediate common-column 2x2 partition could not make the canonical test's staggered lower frame. A failing regression demonstrated the missing arrangement class. The final independent per-row partitions allow a lower frame to bridge the upper pair's column gap. Frame sides vary from 3 through 8 subject to slot size and marker capacity. Canonical acceptance and profile hits are tested; no claim is made that every legal layout or exact canonical pixel arrangement is sampled.

Validation deliberately rejects ragged/empty/noninteger grids, unsupported colors, incomplete or interiorless blue perimeters, blue clutter, nested/overlapping frames, and missing background separation. Generated interiors contain only 0/2, unseeded interiors only 0; exterior red markers are allowed and remain outside every bounding box. Bounds are 2..4 frames, 1..4 markers per active frame, 0..3 exterior markers, 9..20 dimensions. General reference behavior beyond this manifold is not claimed.

For example, using any nonzero interior marker remains equivalent inside the chosen 0/1/2 domain; testing color-specificity against other interior colors is a separate domain expansion.
