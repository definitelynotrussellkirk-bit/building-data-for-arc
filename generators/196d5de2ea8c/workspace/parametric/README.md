# Border-policy parametric prototype

This is an **isolated proposed prototype**. It does not change the selected
canonical generator or its pinned Racket authority.

## Parameter

`border_policy` is chosen exactly once from the deterministic episode seed.

- `exclude_outer` — canonical/default. Find the divider cross, ignore input row
  zero and column zero, and use the modal color of each remaining region.
- `include_outer` — proposed nearby alternative. Use the same divider, regional
  mode operation, and 3×3 output, but include row zero in the upper regions and
  column zero in the left regions.

The object roles, divider detection, regional aggregation, and output layout are
unchanged. Only the three region start indices vary. Retained episodes use the
canonical generator's `close_runner_up` profile, whose ignored border changes an
adjacent mode; all three demonstrations therefore identify the episode setting
before the masked query.

## Reproduce

From the outer extracted packet directory:

```bash
python3 review.py run python3 \
  generators/196d5de2ea8c/workspace/parametric/build_prototype.py \
  --out-dir ../checks/parametric/border-policy-v1
```

The builder refuses to overwrite evidence. It writes one redacted public
challenge and one private evidence file for each setting, both exact Racket
programs and hashes, canonical replay results, source hashes, query answers, and
`summary.json` under `WORK/checks/parametric/border-policy-v1/`.

Public challenges omit the seed, hidden parameter, Racket source, alternative
outputs, and query answer. The Python mirror is only a focused test/debug oracle;
all retained labels are generated by executing the materialized Racket through
the packet bridge.
