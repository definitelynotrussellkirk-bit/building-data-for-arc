# Proposed `branch_map` rule variant for 42f19ef6d600

Status: **proposed task-local prototype only**. It does not modify or approve the
production generator, canonical Racket authority, catalog metadata, or training
admission.

## Rule parameter

The episode fixes one hidden parameter for every demonstration and query:

| `branch_map` | Solid square-bbox object | Non-solid square-bbox object |
| --- | --- | --- |
| `canonical` (default) | complete exterior side strips | eight axial corner-adjacent cells |
| `swapped` | eight axial corner-adjacent cells | complete exterior side strips |

Everything else remains invariant: background 7, same-color 4-connected object
segmentation, square bounding-box requirement with side at least two, output
color 2, and skipping out-of-bounds or originally non-background marks.

The canonical program is byte-for-byte the canonical ledger program and retains
normalized rule hash `07ef8e3cc031` (full SHA-256
`dc177e343a8ee842c8429c04d04ee9a33786f6724242c978984fa856d5f2d029`).
The proposed swapped program has normalized hash `c560f66f174a` (full SHA-256
`581e2a427a20650e56c4e33532028240e1f64aa2bbef2f4ebf4e9531afd606a6`).

## Episode contract

`--demos` is independently configurable from 2 through 4. The first two demos
are a solid and a hollow object, so both branch choices are visible. Additional
demos add mixed and blocked-mark scenes. `--queries` is configurable from 4
through 8. Every query input is distinct from every demo and other query, and
all supported query profiles produce different outputs under the two settings.
The production `size_two_solid` boundary is intentionally excluded here because
for a 2×2 bbox the two mark geometries collapse to the same eight cells; it
would not supervise this hidden parameter.

All stored outputs are generated by the protected Racket bridge. The independent
Python implementation is only a parity/verifier path. Demonstrations must reject
both `always_side_strips` and `always_corner_marks` rivals before an episode is
emitted.

Private JSON includes the fixed setting, exact Racket text and hashes, source
hashes, query labels, profile identities, and parity/rival receipts. Its verifier
replays the deterministic sampler from the stored seed/counts before checking
Racket labels, so altered profile or sample-index provenance is rejected. Public
JSON contains only visible demonstration inputs/outputs and query inputs. The
file bytes are exactly `reviewer_support.public_challenge_bytes(...)`; its full
SHA-256 `public_challenge_id(...)` appears in the opaque
`challenge-<64 hex>.json` filename. Changing a seed, hidden setting field,
private profile metadata, or query answer therefore cannot rename the public
challenge.

## Exact four-query commands

Run these from the outer packet directory, where `review.py` is located:

```bash
mkdir -p WORK/checks/parametric/42f19ef6d600/public

python3 review.py run python3 \
  generators/42f19ef6d600/workspace/parametric/prototype.py generate \
  --branch-map canonical --seed 1701 --demos 4 --queries 4 \
  --private-out ../checks/parametric/42f19ef6d600/canonical.private.json \
  --public-dir ../checks/parametric/42f19ef6d600/public

python3 review.py run python3 \
  generators/42f19ef6d600/workspace/parametric/prototype.py generate \
  --branch-map swapped --seed 1701 --demos 4 --queries 4 \
  --private-out ../checks/parametric/42f19ef6d600/swapped.private.json \
  --public-dir ../checks/parametric/42f19ef6d600/public
```

The generator prints each derived public path. Re-execute and verify each private
file with its printed public file:

```bash
python3 review.py run python3 \
  generators/42f19ef6d600/workspace/parametric/prototype.py verify \
  --private ../checks/parametric/42f19ef6d600/canonical.private.json \
  --public ../checks/parametric/42f19ef6d600/public/challenge-<public-id>.json
```

Generation refuses to overwrite either private or derived public output unless
`--force` is supplied explicitly.
