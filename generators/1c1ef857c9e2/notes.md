## Intended rule

The input is a rectangular grid containing exactly two nonzero ARC colors. The
strict-majority color is the background. The other color forms complete interior
rows and columns. If there are `R` complete separator rows and `C` complete
separator columns, the output is a fresh `(R + 1) × (C + 1)` grid filled with the
background color.

The selected Racket authority is pinned by `RULE_HASH = "13aa128bacd8"`. The
active `racket_target.target_code` is synchronized exactly to the canonical
`program_solution`. The historical `raw_code` is intentionally retained as an
archival divergent source; no rule semantics were changed.

## Current grammar and exact controls

Version `3.0.0` exposes only six observable exact axes:

- `grid_h`, `grid_w`: integers in 7..27.
- `n_sep_rows`, `n_sep_cols`: integers in 1..5.
- `bg_color`, `sep_color`: distinct nonzero colors in 1..9.

Every explicit axis is either honored exactly or rejected loudly. Joint numeric
requests that cannot keep all lines interior while preserving a strict-majority
background raise `ValueError` with an `incompatible_axes` tuple. Unknown keys,
wrong types (including booleans), out-of-range values, and equal role colors are
rejected instead of clamped or ignored.

The public call domain now also requires a literal nonnegative integer
`sample_index`. Both `schedule_profile` and `generate` share `_validate_call`, so
`-1` can no longer wrap into a finite schedule slot. This is the only production
source repair in review `review-cfeefa5f2b4d2d06`; valid generated bytes and the
selected Racket authority are unchanged.

`self_check` validates the complete input law, `observe_overrides` recovers all
six axes, `strict_canonical_like` checks canonical-size support, and
`rule_mirror` independently computes the intended answer.

## Distribution decisions and reversals

The default path stays in the canonical shape/palette family: square inputs of
size 11, 15, 22, or 27 with two nonzero colors. It schedules all 20 asymmetric
pairs `(R, C)` in `1..5 × 1..5` rather than only the four canonical count pairs.
Asymmetry is deliberate: it refutes transposed-count and row-controls-both-axes
shortcuts in every generated lesson.

An intermediate four-pair schedule was rejected because row count predicted
column count and the output population collapsed to four shapes. Expanding to
all 20 asymmetric pairs fixed that, but a first periodic lane still exposed only
six shapes under a realistic seed stream. The final slot is
`(2 * seed + sample_index) % 20`, which exercises all 20 shapes under both the
full-period tests and the probe-like episode stream.

The prior `position_bias` and `texture` aliases were removed. They were not
semantic exact controls, helpful aliases did not create measurable output-law
variation, and the degenerate aliases deliberately violated the task grammar.
Separator locations now vary by keyed RNG while remaining interior; positions
are not advertised as exact controls.

## Teaching contract

Each lesson uses three demonstrations (`EXAMPLES_NEEDED = 3`). Four executable
competitors are declared and checked:

1. omit the `+1` in both output dimensions;
2. transpose row and column counts;
3. fill the output with the separator color;
4. let row count control both output dimensions.

The default grammar makes the required witness for each competitor present in
every sample. `lesson_identifiable` validates demonstration labels and reports a
competitor that fits every demonstration but changes the query.

## Known limits

This generator intentionally covers complete axis-aligned interior separators,
exactly two nonzero colors, strict-majority background, and one query assembled
with three demonstrations. It does not claim support for broken separators,
edge separators, zero as a role color, more than two colors, or arbitrary
out-of-grammar grids. The finite four-rival census is strong evidence against
those named shortcuts, not a proof of unique induction against every possible
hypothesis. The fixed-period census exhausts the declared 20-slot schedule only
at seed 0; the larger census samples 100 starts per band; and the parametric
prototype uses four deterministic episode seeds. None of these finite checks
establishes every conceivable schedule, rule family, or model behavior.

# Decisions for task 1c1ef857c9e2

## D1 — Repair the call contract, not the task law

The canonical transform remains: identify the strict-majority background, count
complete interior separator rows and columns of the other color, add one to each
count, and fill a fresh output of that shape with the background color. The
reproduced defect was acceptance of a negative `sample_index`, not a semantic or
Racket error. I therefore made the smallest source repair: common validation for
both schedule and generation entry points, with a nonnegative-index check.

**Rejected:** changing the schedule arithmetic to special-case negative values.
That would hide an invalid call instead of enforcing the public contract.

## D2 — Keep version 3.0.0 and the selected Racket authority unchanged

`VERSION` stays `3.0.0`, `RULE_HASH` stays `13aa128bacd8`, and neither canonical
JSON nor the selected Racket program changes. All valid calls take the same code
path and produce the same deterministic outputs as before; only an invalid call
now raises. Authority-sync evidence still reports the selected source exactly
synchronized and the historical `raw_code` merely archival/divergent.

**Rejected:** a semantic/version bump or rewrite of the Racket target. Neither is
supported by the defect or needed to preserve valid behavior.

## D3 — Expose only observable exact axes

The production grammar continues to expose exactly six controls: `grid_h`,
`grid_w`, `n_sep_rows`, `n_sep_cols`, `bg_color`, and `sep_color`. Each can be
recovered from a generated input and is either honored exactly or rejected with
a structured incompatibility. Unknown keys, booleans, coercible non-integers,
out-of-range values, equal role colors, and now negative sample indices fail
loudly.

**Rejected:** reviving `position_bias` or `texture`. Those aliases did not define
reliable observable exact controls and could create out-of-grammar examples.

## D4 — Stay in canonical dimensions while broadening semantic counts

Default inputs remain square sizes 11, 15, 22, or 27 with two nonzero colors, so
the generator reaches the canonical profile family. The finite schedule retains
all 20 asymmetric `(separator_rows, separator_cols)` pairs from `1..5 × 1..5`
with equal pairs removed.

**Rejected alternatives:** only the four canonical count pairs, because one axis
then predicted the other and only four output shapes appeared; fully random
sizes/counts, because the baseline had zero exact canonical-profile hits and
schedule coverage became harder to prove.

## D5 — Require asymmetric counts in the default curriculum

Every default pair has different row and column counts. That makes each example
a witness against both transposed-axis and row-controls-both-axes shortcuts.
Equal counts remain lawful through exact overrides when geometrically feasible.

This is a teaching decision, not a statement that equal-count grids are invalid.

## D6 — Use two distinct nonzero colors with a strict-majority background

Both roles stay in colors 1..9 and must differ. The background must occupy more
than half the input, making the Racket `mode` role unambiguous. No decorative
third color, tied mode, or zero role was introduced because none is supported by
the canonical task and each would complicate the meaning of full separator
lines.

## D7 — Use complete interior separators with keyed-random positions

Separator rows and columns remain complete and interior. Their positions vary
through independent keyed random streams but are not exposed as exact axes.
Completeness is the counted primitive; interior placement keeps visible bands on
both sides and matches the reviewed grammar.

**Rejected:** broken or edge separators. They require a different rule family and
are outside the canonical evidence.

## D8 — Preserve the output derivation exactly

For `R` separator rows and `C` separator columns, output shape remains
`(R + 1) × (C + 1)` and every output cell is the background color. The generator
mirror, canonical pairs, Racket smoke checks, and reviewer solve all agree.

## D9 — Keep three demonstrations and four executable competitors

`EXAMPLES_NEEDED = 3`. Production assembles three demonstrations followed by one
query. The declared competitors are: omit the `+1`, transpose row/column counts,
fill with separator color, and use row count for both dimensions. Default
asymmetry and distinct roles provide witnesses against all four.

The contract is intentionally finite. It does not claim universal uniqueness
against undeclared hypotheses.

## D10 — Require both production and query-rotation evidence

I retained two complementary censuses. The fixed seed-0 schedule census enumerates
all 20 declared starts in each of three bands: 60 lessons and 240 rotations. The
larger census samples 100 starts per band: 300 lessons and 1,200 rotations. Both
require zero ambiguity and bind their labels to the final generator and selected
Racket source.

**Rejected:** reporting only ordered-production success. A model-facing query may
occupy another position, so all four rotations are checked explicitly.

## D11 — Treat source-hash changes as evidence invalidation

old schedule-period receipt because it was bound to the baseline generator hash.
I retained that failed run, regenerated the census under the final hash, and fed

**Rejected:** copying or relabelling the old receipt. That would break source
provenance even though the repair is semantically narrow.

## D12 — Choose two nearby, episode-fixed parametric rule axes

The separate prototype varies:

- `measure_mode`: `sections` (canonical/default) versus `separators`;
- `axis_order`: `row_col` (canonical/default) versus `col_row`.

The pair is selected once from the four combinations and held fixed across all
three demonstrations and the query. These axes preserve the same object roles,
counting operation, and output construction while producing distinguishable
labels on the asymmetric production grammar.

**Rejected prototype axes:** color-role inversion, broken-line tolerance, edge
separators, third-color noise, or per-pair parameter resampling. Those either
change the task family, create ambiguity, or teach an inconsistent episode.
