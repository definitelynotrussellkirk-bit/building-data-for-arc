# Retained path counterexamples

Each JSON file contains the full query input, canonical Racket output, and
exact named rival output. The two lesson counterexamples also contain every
demonstration input and its Racket output; their rival outputs are identical to
those demonstration outputs and were checked against the frozen final rival
implementation. These files preserve observed cases, without new labels or
claims of graph or grid minimality.

| Fixture | What it establishes | Evidence population |
|---|---|---|
| `left_up_tie.json` | Left must beat up when the maximum node count ties. `longest_up_before_left` fits all five canonical pairs but chooses up here. | Handmade three-node discriminator, labeled in the final 12-input public Racket application. |
| `endpoint_lesson_ambiguity.json` | A canonical-fit first-step/endpoint rule fits four earlier demonstrations and changes their query. | Actual medium seed 0, demo indices 3–6, query index 7; all five pairs retained. |
| `endpoint_tie_final.json` | Final endpoint-profile support supplies a generated counterexample to that same canonical-fit rule. | Final `tie_down_over_left` representative with explicit profile and 16×18 dimension overrides; no claim that the historical coordinates recur. |
| `physical_distance_lesson_ambiguity.json` | Maximum physical distance fits six intermediate demonstrations and changes the held-out query. This rival fits only two of five canonical pairs, so it is a lesson competitor, not a canonical shortcut. | Actual easy seed 0, indices 0–6, held-out position 4; all seven pairs retained. |
| `shortest_distance_tie.json` | The full direction sequence can choose a physically longer path among paths with the same maximum node count. | Final `complete_direction_order` representative; the shortest-distance rival fits all five canonical pairs. |

The left/up fixture has the smallest node count allowed by the declared
one-red-plus-at-least-two-cyan contract. Its 16×18 canvas is retained padding;
no claim is made that the validator requires that canvas size. All other
fixtures are unminimized observed inputs.

## Earlier support and final support

The endpoint lesson comes from source `162fa5e67ee2…`, which still used the
original five topologies and four-demo schedule. Its recorded hook returned
no reasons, despite the endpoint rival changing the query. The physical-distance
lesson comes from intermediate source `37d464d061d2…`, after the compound
profile was introduced but before the endpoint spacing constraint was added.
These historical lessons are not claims about current production behavior.

Final generator source `b6bb38a23216…` retains the original profile controls,
adds `complete_direction_order`, and uses six demonstrations with a ten-slot
schedule. The compound profile refutes alternative direction orders and the
shortest-distance tie rule. The constrained `tie_down_over_left` profile
refutes endpoint ordering and maximum-distance objectives. Each distinguishing
profile category appears at least twice in a seven-pair cyclic window, so any
one query holdout leaves a distinguishing demonstration. The fixtures retain
the exact full source hashes, rule hash, receipt hashes, result indexes, and
original public application command and working directory.

## Verification and regression coverage

All `official_output` values and demonstration outputs are exact copies from
successful public `arcpuzzles apply` receipts under `WORK/checks/path-analysis/`
or `WORK/checks/path-curriculum-final/`. They were not generated by the Python
audit mirror. Each alternative output was checked against its current named
`LESSON_COMPETITORS` function at the frozen final source. The JSON provenance
paths describe the original review workspace; the full retained grids make
these fixtures independent of those paths for replay. Differing cells use
zero-based row/column coordinates, in row-major order.

Existing tests cover the corresponding generated behavior:

- `../tests/test_contract_regressions.py` checks every declared canonical
  shortcut against every labeled canonical pair.
- `../tests/test_curriculum_support.py` checks generated counterexamples for
  those shortcuts and all declared cyclic starts/query rotations.
- `../tests/test_generator_a55c1997c5e3.py` checks explicit profile behavior,
  boundary dimensions, witness/rival disagreements, and all 23 nonofficial
  constant direction orders on the compound profile.

These tests do not directly load this directory; these files retain the exact
reference-labeled findings that motivated the generated-behavior guards.
`../workspace/probe_path_curriculum.py` separately discovers the live rival
declarations and runs `prepare`, public Racket `apply`, and `score`. Its retained
final proof covers 12 distinct inputs, 34 named callable rival identities, and
70 representative query rotations with no ambiguity. Those symbolic windows
reuse six profile representatives and are distinct from a production census.

For a direct fixture replay, extract its `input` grid, or the demonstration
inputs followed by its query `input`, into a JSON object with an `inputs` list
and call public `arcpuzzles apply a55c1997c5e3`. The complete output can then be
compared with the retained `official_output` values. The current Racket rule is
unchanged from all three source states represented here.
