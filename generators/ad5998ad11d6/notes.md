## 2026-09-28 generator review

The inherited `3.0.0` generator passed all twelve source-bound check stages, but two distribution weaknesses remained outside the named gates:

1. `schedule_profile()` ignored `seed`, so each fixed demonstration/query role always received the same profile modulo the six-item cycle. This leaked lesson structure across the corpus.
2. Every synthetic enclosed component was at most eight cells, including both 20×20 profiles. Canonical demonstrations contain enclosed regions of 15 and 24 cells, so the generator underrepresented canonical scale and admitted a learned `room area <= 8` prior.

Version `3.1.0` seed-rotates an interleaved six-profile cycle. The interleaving keeps a 20×20 profile in every cyclic window of three demonstrations, while the seed rotation prevents a fixed role from owning one morphology. The 20×20 profiles now draw one 12-, 15-, or 24-cell room plus their smaller rooms. The task-local semantic contract now includes the executable rival `rooms_at_most_eight` and witness `canonical_scale_large_rooms`.

Focused regressions cover deterministic exact overrides, same-seed lesson windows, role/profile diversity across seeds, canonical 15/24-cell support, and direct refutation of the size-cutoff rival. The canonical Racket authority and rule hash are unchanged.

Remaining limitation: canonical demonstrations happen to contain only rectangular enclosed components, so `rectangular_rooms_only` still fits the public demonstrations. Generated single-room 10×10 scenes deliberately include nonrectangular rooms to refute it; this is a teaching-distribution requirement rather than a change to the intended topological rule.

# Decisions for `ad5998ad11d6`

## D1. Preserve the canonical transformation and valid generation mapping

**Decision.** Keep version `3.1.0`, canonical program
`(rule! (lambda (g) (fill-all-enclosed g 4)))`, `RULE_HASH 2658bcc9cd0f`, every
lawful seed/index output, and the existing scene distribution unchanged.

**Rationale.** The before battery's ten green stages showed no transformation,
distribution, profile, grammar, or authority defect. The two failures were public
control validation and declaration accuracy. Changing geometry or rule authority
would broaden risk without addressing either root cause.

**Alternatives rejected.** A version bump or seed-map refresh was rejected because
valid generated bytes did not change. A new Racket program was rejected because rule
smoke and authority synchronization were already green.

**Probe / failure boundary.** The complete after battery is 12/12 green and binds the
final source hash. This decision does not assert arbitrary query-rotation support.

## D2. Reject coercible scalar controls at the API boundary

**Decision.** Require literal Python integers for `seed` and `sample_index`, require a
nonnegative sample index, and restrict `difficulty` to `None`, `easy`, `medium`, or
`hard` before entering `gen_ctx`.

**Rationale.** A public deterministic generator should not let `True`, `1.0`, or
`"1"` alias an integer call, nor accept negative indices or undocumented difficulty
names. Validation at the source boundary prevents ambiguous provenance rather than
trying to detect it after generation.

**Alternatives rejected.** Coercing with `int()` preserves the alias. Validating only
inside tests leaves authoring callers exposed. Rejecting all `None` difficulty calls
would break the documented default path.

**Probe / failure boundary.** The focused test covers eleven invalid call shapes and
passed only after the patch. It intentionally does not constrain extra integer range
beyond nonnegative sample indices because no such contract was declared.

## D3. Separate canonical-fitting shortcuts from generated-lesson competitors

**Decision.** Keep all six functions in `SEMANTIC_RIVALS` and
`LESSON_COMPETITORS`, but declare only `rectangular_rooms_only` in
`CANONICAL_SHORTCUTS`.

**Rationale.** `CANONICAL_SHORTCUTS` is an evidence claim about labelled canonical

complexity for a fixed, tested set.

**Probe / failure boundary.** The regression executes the declared canonical rival on
all canonical pairs; the semantic gate exercises the broader lesson registry.

## D4. Retain the ordered three-demo / one-query curriculum

**Decision.** Accept the current ordered production contract and document that
arbitrary query rotation is unsupported.

**Rationale.** The 300-lesson census found 0/300 production ambiguities and no
materialization/scoring failures. Rotation is diagnostic for this curriculum, not the
current runtime policy. Reworking a passing ordered schedule solely to satisfy an
inactive permutation policy would change task distribution and require a broader
review.

**Alternatives considered.** Reordering examples, forcing every four-pair set to
contain multiple large and irregular rooms, or rejection-sampling until every query
rotation is identifiable could reduce the 195 ambiguous rotations. Those options may
also bias morphology, increase rejection cost, and change valid seed mapping. They
belong in a separate rotation-support change with `--require-rotations-identifiable`.

**Probe / failure boundary.** Production: 300/300 identifiable. Rotations: 1,005/1,200
identifiable and 195 ambiguous (193 area-cutoff, two rectangle-only). Evidence is
source-bound and retained in compressed form.

## D5. Build `fill_color` as a separate parametric prototype

**Decision.** Prototype one bounded episode-level parameter: `fill_color ∈ {4,2}`,
with 4 canonical/default and 2 proposed. Select it once per episode, use it for all
three demonstrations and the query, and keep production fixed at 4.

**Rationale.** Output color is a small meaningful rule parameter that changes the
executed transformation without changing object roles, topology, or enclosure
reasoning. It is inferable from demonstrations and requires no input-side encoding.

**Alternatives rejected.** Varying grid size, room position, or sampling weight does
not change the rule. Switching connectivity from 4-neighbor to diagonal would alter
the core topological concept and require a different input manifold. Random colors
without a bounded domain would add palette complexity without stronger evidence.

**Probe / failure boundary.** Both instantiated programs were executed in protected
Racket. Every retained demonstration refutes the other setting, both queries differ,
and color 4 is byte-exact canonical. This remains **prototype / proposed**, not an
approved production variant; finite evidence covers only two values and two episodes.
